## 四、thread_held 投影丢 data bug（本轮发现并修复，决策 16）

- 症状：Phase A 六类操作错误仅 `{code,message}`，无 `data.holderHost`。
- 根因：§3.10 的 `error.data` 保留只落到 Runtime Server 路由层（`request-router.mjs:101`），MCP 最后一跳 `toolErrorContent`（`src/mcp/stdio-bootstrap.mjs`）仍只投影 `{code,message}`；测试断层：core/integration 有 holderHost 断言、bootstrap 投影层零覆盖。
- 修复：`toolErrorContent` 透传 `error.data`；新增 2 单测（socket 序列化错误带 data、throw `ThreadHeldError` 两路径）；223/223、lint 通过。
- 口径澄清：现场曾解读为"fail-closed 不泄漏 holder 属设计"，与实施规格 §3.10（"MCP/内部错误投影必须保留 error.data"）、决策 6/9（holderHost 为错误面组成部分，仅无法确定唯一 holder 时省略）不符；AGENTS.md 禁止泄漏清单不含 holderHost。
